# 邮件批量发送工具（便携版）

给经办用的邮件批量发送小工具：上传文件 → 自动解析类型/平台/客户 → 分组核对 → 一键发送。全程浏览器操作，数据留在本机。

## 目录结构
```
mailer/
├─ 启动.bat              # Windows 双击启动（Win7 可用）
├─ start.sh              # Mac / Linux 启动
├─ server.js             # 后端（Express + nodemailer）
├─ public/index.html     # 前端单页（原生 JS，零构建）
├─ lib/                  # 业务逻辑（配置/模板/发送/日志/账号）
├─ config/邮件配置.xlsx  # 类型与平台配置（在界面里维护，不用碰文件）
├─ tools/                # 命令行小工具（导入模板 / 建配置 / 设账号）
└─ data/                 # 运行时生成：发件账号凭据等（不入库）
```

## 一键启动
- **Windows**：双击 `启动.bat`，自动打开浏览器到 http://localhost:3000
  - 便携包内嵌 Node 12.22.12（最后支持 Win7 的 LTS），Win7/Win10 均可双击即用
- **Mac / Linux**：终端运行 `bash start.sh`

## 浏览器要求（重要）
- 页面用现代 JS 语法，**IE 完全不支持**（IE8–11 内核跑不了，会白屏），请不要用 IE。
- **Win7 请用 Chrome 109 或 Firefox 115 ESR**（最后支持 Win7 的版本），并设为系统默认浏览器。
- **360 安全浏览器（含极速模式）会拦截 `localhost`**：它内置"内网访问保护"，访问 `http://localhost` / `http://127.0.0.1` / `http://192.168.x.x` 时会弹出"当前内网地址暂时无法访问"的拦截页——这是浏览器层面的拦截，**不是白屏、也不是服务没起来**。两种解决：
  1. 直接用 **Edge / Chrome** 打开 `http://localhost:3000`（推荐，最省事）。
  2. 或在 360 里关闭该保护：右上角菜单 → 设置 → 安全设置 → 关闭"开启内网访问保护 / 网站云安全防护"，再刷新。
  3. 另外 360 的"兼容模式"（IE 内核）还会单独造成白屏，与上面拦截是两回事；总之**不建议用 360 跑本工具**。
- 最稳妥：直接装 Chrome / Firefox，别用 IE 和 360。

## 首次配置发件账号（只需一次）
1. 打开页面 → 「账号配置」标签页
2. 服务商选 `qq`（或 `126` / `163`），填邮箱和**授权码**（不是邮箱密码）
   - QQ 授权码：网页邮箱 → 设置 → 账户 → 开启 POP3/SMTP → 生成授权码
3. 保存。凭据存在本机 `data/accounts.json`，仅本机可见（不入库、不上传任何服务器）。

## 日常使用
1. 「模板管理」里维护各类型邮件模板（支持 `{平台名称}` `{客户姓名}` `{日期}` 等变量）
2. 「平台管理」里维护各平台收件邮箱、对接联系人
3. 「上传发送」：上传正文文件（.md/.txt/.html 或表格附件）→ 按文件名自动解析类型/平台/客户 → 分组核对（可编辑、可拖拽）→ 校验 → 确认发送
4. 发送记录在「日志」标签页（CSV 落盘：时间/邮件类型/平台/客户姓名/收件邮箱/抄送/主题/附件/状态/详情/配置行号）

## 安全提醒
- 工具目前**无登录口令**，仅在本机或信任的内网使用。
- 若要放到公网或他人可访问的局域网，**必须先加访问口令**（联系开发）。
- 发件账号凭据只存在本机 `data/accounts.json`，不随代码上传。

## 故障排查
- 双击 `启动.bat` 没反应：确认 `node14\node.exe` 存在（须为 Node 12.x 以兼容 Win7），或系统已装 Node。
- 页面打不开：检查 3000 端口是否被占用；确认启动窗口还在。
- 发送失败：看「日志」标签页的「运行报错日志」（logs/mailer-error.log），多半是授权码错或 SMTP 设置不对。
